# Couchbase Capella Provider 1.12.0: Upgrade and Information Guide

Here is a list of what's new in 1.12.0

## Enhancements

* Adds the `couchbase-capella_bucket_backup_export` data source, exposing the v4 get backup export endpoint
* Adds Terraform-side validation coverage for the Azure storage auto-expansion default change, and fixes the two provider bugs it surfaced
* Fine Grain RBAC Phase 3

- Full RBAC functionality in public API
- Add the ability to create and modify roles

## Bug Fixes

* The existing suite stops at the pending export, which left real gaps:

- **The download URL was never exercised
* `TestAccDatabaseRoleAllScopedLevels` fails its `ImportStateVerify` step about a quarter of the time
* Currently, when a OIDC resource refresh fails on create or update, it will leave the unset fields such as `discovery_url` and `username_claim` in an unknown state
* - Allow setting App Endpoint OIDC providers list with nil, to disable OIDC auth feature
* Consolidates the four Aikido AutoFix pull requests into a single dependency bump, and closes a reachable gap that none of them covered
* Add an IsUnknown() check alongside the existing IsNull() check in internal/resources/cluster

## Changes

1.12.0 includes new features and general improvements. See the [CHANGELOG](https://github.com/couchbasecloud/terraform-provider-couchbase-capella/blob/master/CHANGELOG.md) for more specific information.

## Breaking Changes

WARNING: **ACTION REQUIRED** - The following changes may require updates to your Terraform configurations:


### Add bucket backup export resource

Adds the `couchbase-capella_bucket_backup_export` resource, exposing the v4 create backup export endpoint. An export packages a bucket backup into a zip archive in cloud storage and returns a pre-signed URL for it.

- **Create** posts to `.../buckets/{bucketId}/backups/{backupId}/export`, then refreshes once. It does not wait for the export to finish; a multi-terabyte export can take a long time and the job runs on the backup infrastructure, so create returns while the export is `pending` and the user polls by refreshing. Same shape as `audit_log_export`.
- **Read** calls the GET and refreshes `status`, `size_in_bytes`, `sha256_checksum`, `expiration` and `backup_download_url`. A 404 removes the resource from state, since Capella drops the export record after about seven days.
- **Update** is unsupported. There is no update endpoint and every user-configurable attribute is `RequiresReplace`, so changes plan a replacement.
- **Delete** is a no-op. Nothing can cancel an export, and the archive expires on its own after about twelve hours.
- **Import** takes the standard composite id: `id=<exportId>,backup_id=<uuid>,bucket_id=<id>,cluster_id=<uuid>,project_id=<uuid>,organization_id=<uuid>`. Unlike v1, `backup_id` survives import because the user supplies it.
- `backup_download_url` is `Sensitive`; the URL embeds short lived cloud storage credentials.

The GET plumbing lands here rather than in AV-143191 because create and read both depend on it. #799 adds only the data source on top.
