# Couchbase Capella Provider 1.11.0: Upgrade and Information Guide

Here is a list of what's new in 1.11.0

## Enhancements

* Surface the two Resync progress fields added to the Management API [#754](https://github.com/couchbasecloud/terraform-provider-couchbase-capella/pull/754)

Two read-only attributes were added to the `couchbase-capella_app_endpoint_resync_job` resource and the `couchbase-capella_app_endpoint_resync` data source, exposing progress fields the Management API already returned:

* `docs_targeted` (Number) - the estimated total number of documents to process across the cluster during the resync operation.
* `docs_errored` (Number) - the number of documents that errored during the resync operation.

They sit alongside the existing `docs_changed` and `docs_processed` counters. Previously a resync could only be reported as a raw count of documents processed with no denominator, and a run that finished with some documents failing was indistinguishable from a clean one until `last_error` or `state` was inspected. `docs_processed` against `docs_targeted` now gives progress as a fraction, and a non-zero `docs_errored` identifies a partially failed resync directly.

Both attributes are computed, so no configuration change is needed to pick them up. They are populated on read and can be referenced like any other attribute:

```terraform
output "resync_progress" {
  value = "${data.couchbase-capella_app_endpoint_resync.status.docs_processed} of ${data.couchbase-capella_app_endpoint_resync.status.docs_targeted} documents"
}

output "resync_errors" {
  value = data.couchbase-capella_app_endpoint_resync.status.docs_errored
}
```

## Bug Fixes

* Fix cluster destroy hanging on the status poll
* when cluster deployment fails, the resource is saved to state
* `credential_type`, added to `couchbase-capella_database_credential` , is declared `Optional + Computed` with `Default("basic")` **and** `RequiresReplace`
* #746 only fixed the nil slice; the data source still returned `data = []`
* Pin App Service version to 4.0
* The V4 GET response does not include credentialType, so Read derived it from the presence of userRoles: advanced when roles came back, basic otherwise
* Fix Value Conversion Error on every database credential plan
* Use `List`/`ListNestedAttribute` instead of `Set` for the `access`, `buckets`, `scopes` and `collections` attributes of `couchbase-capella_database_credential`
* `couchbase-capella_query_index_monitor` polled to its own timeout (~60 min) on a `defer_build = true` index instead of returning immediately
* Handle what to do if an App Service enters a failed state during a C-UD op by writing it to the state file with a nice error message
* Unconfigured Optional+Computed attributes are marked unknown at plan time, and `Update` unwraps them with `ValueString()`/`ValueInt64()`, so they reach the API as `""` or `0`
* fixes an issue where after changing data API, provider only waits for any terminal state (ie disabled/enabled) instead of the desired state
* Move version change check to a ModifyPlan validator

## Breaking Changes

WARNING: **ACTION REQUIRED** - The following changes may require updates to your Terraform configurations:

### [AV-139841] Use List/ListNestedAttribute instead of Set for access/buckets/scopes/collections

Four attributes of the `couchbase-capella_database_credential` resource changed from `Set` to `List` in [#749](https://github.com/couchbasecloud/terraform-provider-couchbase-capella/pull/749):

* `access`
* `access[*].resources.buckets`
* `access[*].resources.buckets[*].scopes`
* `access[*].resources.buckets[*].scopes[*].collections`

Lists are ordered, so the position of each element is now significant where it previously was not. `access[*].privileges` is unchanged and remains a set.

`access` is a required attribute, so every configuration that uses `couchbase-capella_database_credential` is affected. The resource does not declare a state upgrader, so state written by 1.10.0 and earlier is read back under the new list semantics without being migrated. After upgrading:

* Run `terraform plan` before applying anything else, and read it carefully.
* If the plan reports a change that only reorders elements of `access`, `buckets`, `scopes` or `collections`, reorder those blocks in your configuration to match the order the plan shows, then re-run `terraform plan` and confirm it is empty.
* Anything that consumed these attributes as sets needs revisiting: `toset()` wrappers, `for_each` over `access`, and any module output that relied on set semantics. Element order is now whatever the configuration and the API return, so indexed references such as `access[0]` are only stable once the plan is clean.

See the [database credential examples](https://github.com/couchbasecloud/terraform-provider-couchbase-capella/tree/main/examples/database_credential) for the current shape.

## Changes

There are no deprecations as part of this release.

1.11.0 includes new features and general improvements, along with one breaking change to the `couchbase-capella_database_credential` resource described above. See the [CHANGELOG](https://github.com/couchbasecloud/terraform-provider-couchbase-capella/blob/master/CHANGELOG.md) for more specific information.
